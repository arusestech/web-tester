# wigo-web-tester 시나리오 JSON 작성 가이드

이 문서는 **Claude 등 AI 도구 없이** 사람이 직접 테스트 시나리오 JSON을 만드는 방법을 설명한다.
시나리오 하나 = 프로젝트 하나. 만들어 두면 `run.sh scenarios/xxx.json` 으로 누구나 반복 실행하고 증적을 뽑을 수 있다.

---

## 0. 먼저 알아둘 것

- 파일 위치: `wigo-web-tester/scenarios/<프로젝트명>.json` (다른 경로도 가능)
- 인코딩: **UTF-8** (한글 깨짐 방지. 메모장이면 "다른 이름으로 저장 → 인코딩 UTF-8")
- `_comment_...` 처럼 `_` 로 시작하는 키는 프로그램이 무시한다 → 메모용으로 자유롭게 사용
- 문법 검사: `node -e "require('./scenarios/xxx.json')"` 가 에러 없이 끝나면 OK
  (VS Code 등 편집기를 쓰면 빨간 줄로 바로 알려준다)

### 프로젝트 / 폴더 구조
```
scenarios/
  스타벅스VOC/            ← 프로젝트 (최상위 폴더)
    조회/                 ← 폴더 (깊이 자유)
      voc-menus.json
      stats.json
    권한/
      P01-R100.json
      ...
  우리은행VOC/
    voc.json
  example.json           ← 최상위에 두면 "(미분류)" 처럼 그냥 목록에 보임
```
- **프로젝트 = `scenarios/` 바로 아래 폴더.** GUI 상단(제목 옆)에서 프로젝트를 고르거나 **＋ 새 프로젝트**로 만든다. 왼쪽 트리는 선택한 프로젝트 안의 폴더·시나리오만 보여준다. 기본 프로젝트 **`기본`** 은 항상 있고, `scenarios/` 최상위에 굴러다니는 시나리오 파일은 프로그램 시작 시 자동으로 `기본/` 으로 옮겨진다 (`example.json` 제외).
- 사이드바 상단 **▶ 전체** = 프로젝트 전체 일괄 실행. 폴더를 클릭하면 그 폴더 아래 전부 일괄(폴더 옆 ▶ 도 동일), 시나리오 하나를 클릭하면 그것만.
- **이동/복사**: 시나리오 위에 마우스를 올리면 나오는 ⋯ → "이동·복사", 폴더 ⋯ → 5) 이동·복사 → 대상 프로젝트와 그 안 폴더 선택 → [이동] 또는 [복사]. 프로젝트 ⋯(상단) 으로 이름 변경/삭제.
- 증적은 시나리오와 **같은 폴더 구조**로 쌓인다: `reports/스타벅스VOC/조회/voc-menus-<시각>/`. 일괄 실행은 `reports/<프로젝트or폴더>/<폴더명>-일괄-<시각>/` 안에 **합산 report.html** + 시나리오별 하위 폴더 (항목명 `[시나리오명] 메뉴명`).
- GUI 증적 탭은 **왼쪽에서 선택한 시나리오/폴더의 증적만** 보여준다 ("전체 보기" 체크로 모두). 트리의 폴더는 클릭하면 선택, 선택된 폴더를 다시 클릭하면 접기/펴기(상태 기억). 편집 탭의 설정 카드(기본/로그인/…)도 제목 클릭으로 접기/펴기.
- `{{password}}` 같은 자리표시자는 일괄 실행 시 **같은 이름이면 한 번만 묻고 전체에 적용**. 프로젝트마다 계정이 다르면 자리표시자 이름을 다르게(`{{pw_star}}`, `{{pw_wrb}}`) 두면 각각 묻는다.
- 터미널: `run.bat scenarios\스타벅스VOC --mode menus --headless` (폴더를 주면 일괄), `run.bat scenarios\스타벅스VOC\조회\voc-menus.json` (하나만)
- 폴더 만들기: GUI **＋ 프로젝트/폴더** (`스타벅스VOC/조회` 처럼 한 번에 여러 단계 가능) 또는 탐색기에서 그냥 폴더 생성. 폴더의 **⋯** 로 하위 폴더 추가·이름 변경·삭제.
- 시나리오 이동: 편집 탭 상단 **저장 위치/파일명** 을 바꿔 저장 → "이동" 또는 "복사본" 선택. `_` 로 시작하는 폴더/파일은 목록과 일괄 실행에서 제외(보관용).

### 만드는 방법
| 방법 | 언제 | 어떻게 |
|---|---|---|
| ⓪ 📂 소스에서 만들기 (소스가 있으면 가장 빠름) | 프로젝트 소스를 볼 수 있을 때 | 편집 탭 **📂 소스에서 만들기** → 소스 폴더 지정 → 접속 URL·로그인·메뉴·금지 버튼·expect 초안이 한 번에 (2-5 아래 참고) |
| ① GUI 편집 탭 (권장) | 대부분의 경우 | `WigoWebTester.bat` → 왼쪽 **＋ 새 시나리오** → 폼 입력 → 저장 위치 선택 → 저장. 메뉴는 "여러 줄 붙여넣기"로 `메뉴명 | URL` 을 한 번에 |
| ② GUI ⏺ 녹화 | CRUD 흐름, 클릭으로만 들어가는 메뉴 | 브라우저에서 손으로 조작하면 스텝이 기록됨 (2-8 참고) |
| ③ GUI "JSON 직접 편집" | iframe 옵션 등 폼에 없는 항목 미세 조정 | 편집 탭 우상단 체크박스 전환 |
| ④ 기존 파일 복제 | 비슷한 프로젝트가 있을 때 | `scenarios/starbucks-voc.json` 복사 후 URL/셀렉터만 교체 |
| ⑤ 터미널 마법사 | GUI 를 못 쓰는 서버 | `run.sh new` |

①로 뼈대를 만들고 이 문서를 보며 다듬는 것을 권장한다. 폼 편집은 로그인 `steps` 를 "아이디→비밀번호→버튼→(이동)" 표준형으로 다시 쓰므로, JSON 으로 특수한 로그인 스텝을 넣었다면 이후엔 ②로 편집한다.

## 1. 전체 구조

```json
{
  "name": "프로젝트명",                 // 증적 폴더명에 쓰임
  "extends": "_공통.json",               // 공통 설정 상속 (선택) → 2-0
  "baseUrl": "http://localhost:8080/ctx", // 상대 URL의 기준 (컨텍스트 경로까지)
  "browser":  { ... },                   // 브라우저 옵션
  "evidence": { "screenshotAll": true }, // 모든 화면 캡처 여부
  "forbidden": [ ... ],                  // 절대 누르면 안 되는 버튼 텍스트
  "blocked":  [ ... ],                   // "권한 없음" 으로 볼 증상 정규식 (매트릭스에서 🚫) — 선택
  "retry": 1,                            // 실패한 화면 재시도 횟수 (불안정 대비) — 선택, 기본 0
  "slowMs": 5000,                        // 이 시간을 넘으면 ⚠️ 느린 화면 — 선택, 0/생략이면 검사 안 함
  "timeout": 10000,                      // 요소 대기 기본값(ms). 메뉴별로 덮어쓸 수 있다
  "expectTimeout": 8000,                 // 핵심 요소(expect)를 기다리는 시간 — 선택, 기본 timeout 의 절반(최소 3초)
  "loading": "#loading, .spinner",       // 로딩 표시 — 사라질 때까지 기다린 뒤 판정 — 선택
  "emptyWait": 1500,                     // 화면이 비어 보일 때 다시 읽어 보는 시간(ms) — 선택, 기본 1500
  "checks": { "images": true, "layout": false }, // 깨진 이미지 / 가로 스크롤 검사 — 선택
  "mask": ["#custNm", "td.phone"],       // 스크린샷에서 가릴 개인정보 요소 — 선택
  "login":    { ... },                   // 로그인 방법
  "menus":    [ ... ],                   // 화면 목록 (핵심)
  "crawl":    { ... },                   // 링크 자동 수집 (선택)
  "crud":     [ ... ]                    // 조작 흐름 (선택)
}
```

필수는 `baseUrl`, `menus` 뿐이다. 나머지는 없어도 돌아간다.

### 2-0. `extends` — 공통 설정 상속 (권한/역할 시나리오에 필수)

같은 사이트를 계정만 바꿔 가며 테스트할 때(권한 페르소나 24개 등) 접속 URL·메뉴 목록·금지 버튼·조회 조건을 파일마다 복사하면
메뉴 하나 늘 때마다 24군데를 고쳐야 한다. 공통 부분을 한 파일에 모으고 나머지는 상속한다.

```
scenarios/스타벅스/02_권한/
  _공통.json          ← 공통 설정 (앞에 _ 를 붙이면 목록·일괄 실행에서 제외된다)
  auth-P01-R100.json  ← { "extends": "_공통.json", "name": "P01 시스템관리자", "login": { "steps": [...아이디만 다름...] } }
  auth-P02-R110.json
```

| 규칙 | 내용 |
|---|---|
| 경로 | 자기 파일 기준 상대경로(`_공통.json`, `../_공통.json`) 또는 `scenarios/` 기준 경로(`스타벅스/_공통.json`). `.json` 생략 가능 |
| 여러 개 | `"extends": ["_사이트.json", "_메뉴목록.json"]` — 순서대로 겹쳐 쓰고 **뒤에 온 것이 우선** |
| 병합 | 객체(`login`, `inputs`, `browser` …)는 **깊게 병합**, 배열·숫자·문자열은 자식 값이 **통째로 교체** |
| 목록 더하기/빼기 | `"menusAdd": [ {...} ]` 상속받은 메뉴에 추가 · `"menusExclude": ["통계", "^관리자"]` 이름 정규식으로 제외 (`crudAdd`/`crudExclude` 도 동일) |
| 다단계 | 상속 대상이 또 다른 파일을 상속해도 된다 (순환은 오류) |

로그인 계정만 다른 자식은 이 정도면 끝난다. `steps` 는 배열이라 **통째로 교체**되므로 스텝 전체를 다시 쓴다
(비밀번호는 공통 파일과 똑같이 `{{password}}` 로 두면 실행할 때 한 번만 입력받아 전체에 적용된다).

```json
{
  "extends": "_공통.json",
  "name": "P05 VOC 관리자",
  "login": { "steps": [
    { "action": "fill", "selector": "#userId", "value": "test05" },
    { "action": "fill", "selector": "#password", "value": "{{password}}" },
    { "action": "click", "selector": "#btnLogin" }
  ]}
}
```

GUI 편집 탭에서 상속 시나리오를 열면 위에 **🔗 상속 중** 배너가 뜨고, 폼에는 **상속까지 합친 실행값**이 보인다.
저장하면 상속 대상과 **다른 값만** 그 파일에 남으므로 공통 설정은 계속 상속된다. 공통값 자체를 고치려면 `_공통.json` 을 열어 고친다.

## 2. 항목별 작성법

### 2-1. `baseUrl` — 접속 주소 찾기
컨텍스트 경로까지 포함해야 상대 URL이 맞게 붙는다.

| 어디서 | 무엇을 |
|---|---|
| 톰캣 `conf/server.xml` | `<Connector port="8080"` → 포트 |
| 톰캣 `webapps/` 폴더명 또는 `build.gradle`/`pom.xml` 의 war 이름 | `voc.war` → 컨텍스트 `/voc` |
| IntelliJ Run Configuration → Deployment 탭 | Application context |
| 브라우저 주소창 | 그냥 로그인 화면 URL에서 화면 경로를 뺀 것 |

예) `http://localhost:8080/voc`

### 2-2. `browser`
```json
"browser": { "channel": "chrome", "headless": false, "slowMo": 0, "viewport": { "width": 1600, "height": 950 } }
```
- `channel`: `chrome` / `msedge`. 둘 다 없으면 이 줄을 지우고 `npx playwright install chromium`
- `headless`: `true` 면 창 안 보임(서버/CI용)
- `slowMo`: 밀리초. 눈으로 확인하고 싶으면 `300` 정도
- `viewport`: 화면 크기. 가로 스크롤 나는 화면이면 키운다

그 외 최상위 옵션: `"timeout": 15000` (요소 대기 ms), `"stepDelay": 500` (스텝 사이 쉬는 ms)

### 2-2b. 증적(스크린샷) 범위
세 단계로 정한다. 아래로 갈수록 우선순위가 높다.

| 단계 | 어디서 | 값 |
|---|---|---|
| ① 시나리오 기본 | `"evidence": { "screenshotAll": true }` | `true` 모든 화면 / `false` 실패한 화면만 |
| ② 실행할 때 | GUI 실행 탭 "증적 캡처" 또는 `--screenshot all\|fail\|none` | `all` 모든 화면 / `fail` 실패만 / `none` 안 찍음 (①을 덮어씀) |
| ③ 항목별 | 메뉴·CRUD 흐름·`detail` 에 `"screenshot": true` 또는 `false` | `true` 항상 찍음 / `false` 실패해도 안 찍음 (①②보다 우선) |

```json
{ "name": "개인정보조회로그", "url": "/screen/SYS0171.ub", "screenshot": false },
{ "name": "전체 VOC", "url": "/screen/VOC1001.ub", "screenshot": true }
```
평소엔 ②를 `fail` 로 돌려 빠르게 확인하고, 제출용 증적을 뽑을 때 `all` 로 돌리는 식으로 쓴다. 개인정보가 보이는 화면은 ③ `false` 로 고정해 두면 실수로 캡처되지 않는다. CRUD 스텝의 `screenshot` 액션은 `none` 일 때만 생략된다.

### 2-3. `forbidden` — 안전장치 (가장 먼저 채울 것)
클릭하려는 버튼이 여기 항목(정규식)과 매칭되면 **클릭하지 않고 실패로 기록**한다.
버튼의 글자뿐 아니라 `title`·`value`·`aria-label`·안쪽 `img` 의 `alt`·`id`·`name` 까지 본다 — 글자 없는 아이콘 버튼(휴지통 그림, `#btnDelete`)도 걸린다. 스텝 `click`·버튼 동작 검사(`actions`)·상세 행 클릭 모두 같은 기준이다.
공유 DB, 실제 메일/SMS 발송, 결제, 결재 등이 있는 시스템에서는 반드시 채운다.

```json
"forbidden": ["삭제", "영구삭제", "발송", "강제실행", "상신", "승인", "반려", "마감", "저장", "Save", "Delete"]
```
- 소스에서 찾기: JSP 전체를 `발송|삭제|강제|결제|승인` 으로 검색해 위험 버튼 텍스트를 모은다.
- 영문 title 속성(`title="Delete"`)으로 된 버튼도 있으니 영문도 넣는다.
- 조회만 하는 시나리오라면 `저장`까지 넣어 두는 것이 안전하다.
- **확인창(confirm)**: 메뉴 순회(화면 진입·`actions`·`detail`·`crawl`) 중에 뜬 confirm/prompt 는 **취소**한다(행 클릭이 띄운 "삭제하시겠습니까?" 에 확인을 눌러 데이터가 바뀌는 사고 방지). 메시지가 `forbidden` 에 걸리면 ❌ `금지 동작 확인창 차단`, 아니면 ⚠️ `다이얼로그: confirm: … [취소함]`. 로그인과 `crud` 흐름은 지금처럼 자동 확인. 조회용 confirm 이라 눌러야 하면 시나리오·메뉴·`detail`·버튼에 `"confirm": "accept"`.

### 2-3b. `ignore` — 노이즈 무시 패턴
환경 탓에 **모든 화면에서 반복되는** 경고(⚠️)를 보고서에서 빼서 진짜 문제만 남긴다. 정규식 배열.
```json
"ignore": {
  "console":   ["Content Security Policy", "jQuery Migrate"],
  "resources": ["cdnjs\\.cloudflare\\.com", "/page/images/", "favicon"],
  "dialogs":   ["승인되지 않은 도메인"],
  "text":      []
}
```
| 키 | 무엇에 적용 | 예 |
|---|---|---|
| `console` | 콘솔 에러 메시지, JS 예외 메시지 | CDN 차단 CSP 경고, 라이브러리 deprecation |
| `resources` | 4xx/5xx 응답·실패 요청의 **URL** (그 리소스의 "Failed to load resource" 콘솔 에러도 함께 제외). 화면·AJAX(document/xhr/fetch)의 **5xx 는 ⚠️ 가 아니라 ❌ `서버 오류 응답`** 이므로, 환경 탓이 확실할 때만 여기로 뺀다 | 컨텍스트 빠진 이미지 404, 외부 CDN |
| `dialogs` | alert/confirm 메시지 | 에디터 라이선스 alert |
| `text` | 에러 페이지 패턴 매칭 결과 | 본문에 "Exception" 단어가 정상적으로 들어가는 화면 |

**순서**: 먼저 무시 없이 한 번 돌려 보고서를 읽고, "환경 문제"로 판단한 것만 넣는다. 넣은 이유를 `_comment_ignore` 에 적어 둔다. 무시한 항목이라도 실제 버그면 별도로 개발팀에 전달한다.

### 2-4. `login`
```json
"login": {
  "url": "/screen/BCO0001.ub",
  "steps": [
    { "action": "fill",  "selector": "#userid", "value": "test01" },
    { "action": "fill",  "selector": "#userpw", "value": "{{password}}" },
    { "action": "click", "selector": "#login" },
    { "action": "waitForLoad", "state": "networkidle" }
  ],
  "success": { "urlNotContains": "login" }
}
```

**셀렉터 찾는 법 (크롬 개발자도구)**
1. 로그인 화면에서 F12 → 요소 선택 화살표(Ctrl+Shift+C) → 아이디 입력란 클릭
2. `<input id="userid" name="userid">` 이면 셀렉터는 `#userid` (id 우선) 또는 `input[name=userid]`
3. 로그인 버튼이 `<button>`이 아니라 `<div id="login">`, `<a>`, `<img>` 인 경우가 많다 → 그 요소의 id/class 를 쓴다
4. 확신이 없으면 개발자도구 Console 에서 `document.querySelector('#login')` 을 쳐서 그 요소가 나오는지 확인

**success (로그인 성공 판정)** — 하나 이상 지정. 전부 만족해야 성공.
| 키 | 의미 | 예 |
|---|---|---|
| `urlNotContains` | URL에 이 문자열이 **없으면** 성공 (로그인 페이지 벗어남) | `"login"`, `"BCO0001"` |
| `urlContains` | URL에 이 문자열이 있으면 성공 | `"main"`, `"POR0001"` |
| `text` | 화면 본문에 이 텍스트가 있으면 성공 | `"로그아웃"`, 사용자 이름 |
| `selector` | 이 요소가 보이면 성공 | `"#menu"`, `"#gnb"` |

**`detect` (로그인 화면 감지)** — `"detect": "#loginId"`. 미로그인 접근 시 302 로 튕기지 않고 **200 + 로그인 폼**을 내려주는 사이트(우리은행 VOC 등)는 상태코드로는 세션 끊김을 못 잡는다. 이 요소가 어느 화면에서든 (화면에 실제로 보이면) ❌ "로그인 화면으로 돌아감" 으로 기록. `#loginId` 처럼 **미인증일 때만 나타나는** 요소를 쓴다.

**`retries` / `after` (AJAX 로그인 경합)** — 로그인이 폼 전송이 아니라 AJAX POST 후 `location.href` 로 이동하는 사이트는 세션 커밋과 이동 사이 경합으로 **간헐적으로 로그인이 안 붙는다**. `"retries": 3`(기본 3) 이면 `detect`/`success` 로 실패를 감지해 자동 재시도한다. `"after": "/"` 는 재확인 시 다시 접속할 로그인 후 화면(기본 `/`).

**사이트별 오류 규약** (최상위)
```json
"errorStatus": [486, 487, 488],
"errorPatterns": ["\"errorCode\"\\s*:\\s*48\\d", "권한이 없는 메뉴입니다"]
```
- `errorStatus`: 이 상태코드 응답(AJAX 포함)은 ⚠️ 리소스 응답이 아니라 ❌ **업무오류 응답**으로 기록
- `errorPatterns`: 본문(iframe·모달 포함)에 이 정규식이 나오면 ❌ 에러 페이지 감지. 모달 안에 `{"errorCode":488}` 이 그대로 찍히는 사이트용

**주의할 패턴**
- 비밀번호를 JS가 암호화(SHA256 등)해서 보내는 사이트 → 그래도 **평문을 입력**하면 된다. 우리는 화면을 조작하는 것이지 요청을 만드는 것이 아니다.
- 로그인 후 이상한 곳(404 등)으로 가는 사이트 → `steps` 마지막에 `{ "action": "goto", "url": "/main" }` 을 넣어 메인으로 직접 이동시킨 뒤 `success` 를 판정한다. (스타벅스 VOC 예제가 이 경우)
- 로그인 후 alert 가 뜨는 사이트 → 자동으로 수락된다. 메시지는 보고서에 기록됨.
- **비밀번호는 파일에 저장하지 않는 것이 원칙.** `"value": "{{password}}"` 로 두면(GUI 편집 탭의 "실행할 때 입력" 체크) 실행 직전에 팝업으로 입력받아 이번 실행에만 쓴다. 터미널/CI 는 `--secret password=값` 또는 환경변수 `WWT_password`. 자리표시자 이름은 자유(`{{id}}`, `{{otp}}` 등 여러 개 가능).
- 그래도 평문을 넣었다면 **파일을 git에 올리지 말고** 공유는 사내 경로로만 한다. 반입 번들은 `--no-scenarios` 로 만들어 시나리오를 빼고 가져간다.

### 2-5. `menus` — 화면 목록 (핵심)
```json
"menus": [
  { "name": "VOC 업무 > 전체 VOC", "url": "/screen/VOC1001.ub", "expect": ["table.ui-jqgrid-btable"] },
  { "name": "시스템 > 부서관리",   "url": "/screen/SYS0159.ub" }
]
```
- `name`: 보고서에 찍히는 이름. `대메뉴 > 소메뉴` 형태로 쓰면 읽기 좋다. 위험 화면은 `(조회만)` 을 붙여 두면 나중에 보는 사람이 안심한다.
- `url`: `baseUrl` 기준 상대 경로. 절대 URL도 가능.
- `expect`: 이 화면에서 **꼭 보여야 하는 요소**. 없으면 ❌. 목록 화면이면 테이블, 등록 화면이면 폼/저장 버튼. 생략 가능하지만 넣을수록 "떴는데 빈 화면" 을 잡아낸다.
- `expectFail`: **이 항목은 실패해야 정상**이라고 선언(예: 이 계정엔 막혀야 하는 메뉴, 없어진 화면). 예상대로 실패하면 ❌ 가 아니라 🔒(예상된 실패)로 처리되어 **실패 카운트에서 빠진다**. CRUD 흐름에도 쓸 수 있다.
  - `true` → 어떤 실패든 예상된 것으로 본다. (예: `"expectFail": true`)
  - 정규식 문자열/배열 → **그 사유로 실패했을 때만** 🔒. 다른 원인으로 실패하면 그대로 ❌ + "다른 원인으로 실패 — 확인 필요" 경고. (예: `"expectFail": "권한이 없|접근권한이 없|HTTP Status 403"`)
  - 막혀야 하는데 **실패하지 않으면** ⚠️ 경고("예상과 달리 실패하지 않았습니다") — 권한이 잘못 열렸는지 알 수 있다.
  - ⚠️ 주의: 권한 페르소나(§2-0)의 `menus` 는 "**접근 가능해야 하는**" 메뉴다. 거기서 권한 거부가 뜨면 그건 진짜 ❌ 다. `expectFail` 은 "이 계정엔 **막혀야** 하는" 특정 메뉴에만 붙인다.

> ⚠️ **expect 는 소스 JSP 의 id 를 그대로 믿지 말 것 — 반드시 "실제 렌더된 화면에 보이는" 요소여야 한다.** 소스에 있는 요소가 런타임엔 없거나 숨겨진 경우가 많다. 특히:
> - **메타(uxl/전자정부 등) 화면**: 소스 JSP 구조 ≠ 런타임 DOM. 메타 페이지가 다시 그리므로 소스의 form/table id 가 안 나올 수 있다.
> - **트리(dynatree 등) 화면**: 검색폼이 없고 트리+상세폼 구조인 경우가 많다. 소스에 `<form id="searchForm">` 가 있어도 **`display:none`** 이면 "보이는 요소" 가 아니라 ❌ 가 된다. 트리 컨테이너 div(`#vocCauseTree` 등)나 상세폼처럼 실제 보이는 것을 쓴다.
> - **팝업(`window.open`) 화면**: 직접 URL 로 열면 렌더가 달라질 수 있다. 발송/등록 폼이면 그 폼(`#registForm`)이나 핵심 입력(textarea 등)을 쓴다.
> - **jqGrid**: 정적 컨테이너는 `#list`(class `ub-control grid`)이고, `table.ui-jqgrid-btable` 은 **데이터와 함께 초기화된 뒤 생기는 동적 클래스**다. 빈 그리드·느린 초기화면 없을 수 있으니 **컨테이너 id(`#list`) 나 데이터 무관 요소를 우선**한다.
>
> **검증 순서**: 소스로 후보를 잡되, **첫 실행의 report/스크린샷으로 "핵심 요소 없음: … (N초 대기)" ❌ 가 났는지 확인**하고, 스크린샷에 실제로 보이는 요소로 확정한다. 소스만 보고 넣은 expect 는 검증 전까지 잠정값이다. (2026-08-29: 스타벅스 VOC 의 VOC1026/STC0102(트리)·POP0007(팝업 jqGrid)에서 이 함정으로 오탐 발생 → 트리 컨테이너·발송폼으로 교체.)

**메뉴 URL 목록 뽑는 곳 (우선순위 순)**
| 소스 | 찾는 법 |
|---|---|
| 메뉴 테이블 덤프 / 메뉴 관리 화면 | `MENU_NAME, CONNECT_URL` 컬럼 → 그대로 표로 옮긴다. 가장 정확 |
| 메뉴 XML 매퍼 쿼리 | `selectMenu`, `MENU` 가 들어간 쿼리에서 테이블명 확인 후 DB에서 조회 |
| 사이드바/탑메뉴 JSP | `menu.jsp`, `left.jsp`, `top.jsp`, `include/` 아래 `<a href=` |
| 컨트롤러 | `@RequestMapping`, `@GetMapping` 값 전부 검색 |
| `web.xml` | `<servlet-mapping>` 의 url-pattern (구형 프로젝트) |
| 브라우저 | 실제로 메뉴를 하나씩 클릭하며 주소창을 복사 (프레임이면 F12 → Network 에서 문서 요청 URL) |

**화면 ID → URL 변환 규칙**이 있는 프레임워크(예: `VOC1001` → `/screen/VOC1001.ub`)면 규칙만 알면 CSV에서 일괄 생성할 수 있다.

**📂 소스가 있을 때 — 소스에서 만들기(scan-source)**
프로젝트 소스 폴더를 정적 분석해서 **접속 URL · 로그인 · 메뉴 · 금지 버튼 · expect · 조회 조건 후보**를 한 번에 뽑는다.
**서버가 안 떠 있어도 되고, 로그인도 필요 없다**(파일만 읽는다). GUI 는 편집 탭 메뉴 목록의 **📂 소스에서 만들기**.
```
run.bat scan-source D:\source\myproject --out scenarios\내프로젝트\초안.json
run.bat scan-source D:\source\myproject --append scenarios\내프로젝트\기존.json   # 새 메뉴만 추가
```
| 옵션 | 뜻 |
|---|---|
| `--out` | 시나리오 초안 파일로 저장 (없으면 화면에만 출력) |
| `--append` | 기존 시나리오에 **새 메뉴만** 추가 |
| `--name` | 시나리오 이름 (기본: 소스 폴더 이름) |
| `--url` | 접속 URL 을 직접 지정 (기본: 소스의 포트·컨텍스트로 추정) |
| `--user` | 로그인 스텝에 넣을 테스트 계정 ID (없으면 `{{userId}}` — 실행할 때마다 물어본다) |
| `--pattern` | 화면ID → URL 규칙 (`"/screen/{}.ub"`). 생략하면 소스의 문자열에서 자동 추론 |
| `--limit` | 메뉴 수 상한 (기본 800) |
| `--no-expect` | expect·조회조건·상세 후보를 뽑지 않음 (빠름) |

**어디서 뽑아 오나** (확신도 순)

| 출처 | 내용 |
|---|---|
| 메뉴 테이블 INSERT (`*.sql`, 매퍼 XML) | `MENU_NM` + `MENU_URL` + 상위메뉴 → `대메뉴 > 소메뉴` 이름까지. 가장 정확 |
| 화면 정의 XML (메타 프레임워크) | `<screenBuilder id="VOC1001"><screenName>VOC 목록</screenName>` → 화면ID + 이름 (uBridge/uxl 등) |
| 메뉴 JSP (`menu/left/top/lnb/gnb`) | `<a href>` · `onclick` 경로 · `data-menu-url` 같은 속성 |
| 컨트롤러 | `@GetMapping` 등 (POST 전용·`@ResponseBody` API·모달·경로변수는 제외). 메서드 **바로 위** 주석이 메뉴 이름 |
| 로그인 JSP | 아이디/비밀번호/버튼 셀렉터, 로그인 URL, `detect`(이게 보이면 로그인 실패) |
| 모든 JSP 버튼 텍스트 | 삭제·발송·결제… → `forbidden` 후보 (횟수와 함께) |
| 화면 JSP | jqGrid/toastUI/table id → `expect` 후보, 조회 폼 input → 조회 조건 후보, `ondblClickRow` → 상세 후보, **버튼 목록**(마크업 버튼 + `$('#btnRegister')` 처럼 스크립트에서만 다루는 버튼) |

- 근거(**파일:줄**)와 **제외한 것의 이유**는 `reports/_소스분석/<이름>-<시각>/source-scan.html` 에 전부 남는다. GUI 는 결과 위 링크.
- `_backup`·`_old` 파일과 주석 안의 매핑은 무시한다(주석 처리된 옛 컨트롤러를 메뉴로 잡지 않기 위해).
- **버튼**: 화면마다 버튼 목록을 초안의 `_버튼` 과 보고서 "화면별 버튼" 표에 남긴다(⚠ = `forbidden` 에 걸려 실행 중 차단되는 버튼).
  - `--actions`(GUI 는 **🖱 버튼 동작 검사도 만들기**)를 주면 **조회·검색·초기화처럼 데이터를 바꾸지 않는 버튼만** 골라 `actions`(버튼 동작 검사)로 만들어 준다.
  - 등록·저장·삭제·발송·엑셀 버튼은 **일부러 넣지 않는다** — 누르면 데이터가 바뀌고, 무엇이 나와야 정상인지·필수 입력값을 소스에서 정할 수 없기 때문. 그런 흐름은 **⏺ 녹화**로 `crud` 에 만든다.
- **상세 진입(`detail`)은 자동으로 넣지 않는다** — 행 클릭이 데이터를 바꾸는 화면이 있기 때문. 후보만 초안의 `_상세후보` 와 보고서에 적어 둔다.
- **조회 조건 값도 자동으로 넣지 않는다** — 날짜 형식·기간 제한을 모르기 때문. 설명(`inputs.labels`)과 조회 버튼만 넣고 값은 직접 채운다.
- **한계**: 권한에 따라 달라지는 메뉴, JS 로 그리는 메뉴, 메뉴 URL 이 DB 에만 있는 화면은 못 본다 → 아래 **discover** 로 보완한다.
- 실측 (2026-08-31): Spring Boot+Tiles 프로젝트에서 사람이 만든 109개 중 **92개**(나머지는 경로변수·DB 전용 주소), 메타 프레임워크(uBridge) 프로젝트에서 **61/61 + 로그인 설정 완전 일치**. 둘 다 1초 안팎.

**🔍 소스를 못 볼 때 — 화면에서 메뉴 수집(discover)**
소스도 메뉴 테이블도 못 보는 환경(운영 화면만 있는 경우)에서는 도구가 직접 로그인해서 링크를 긁어 메뉴 초안을 만든다.
```
run.bat discover scenarios\프로젝트\my.json --url /main.do --depth 2 --append
```
GUI 는 편집 탭 메뉴 목록의 **🔍 화면에서 메뉴 수집** 버튼 → 결과를 체크박스로 고른 뒤 [선택한 메뉴 추가].

| 옵션 | 뜻 |
|---|---|
| `--url` | 시작 화면 (기본 `/`). 보통 로그인 후 메인 |
| `--depth` | 1 = 시작 화면의 링크만, 2 = 그 링크들을 열어 한 단계 더 (기본 1) |
| `--pages` | 열어 볼 화면 수 상한 (기본 20) |
| `--max` | 수집할 메뉴 수 상한 (기본 200) |
| `--selector` | 링크 셀렉터 (기본 `a`). 메뉴 영역만 긁으려면 `"#lnb a, .gnb a"` |
| `--pattern` | 화면ID → URL 규칙 (예: `"/screen/{}.ub"`, 슬러그형이면 `"/{}"`). 생략하면 **시나리오의 기존 메뉴 URL 에서 자동 추론**(가장 많이 쓰인 모양) |
| `--append` | 시나리오 `menus` 에 **새 URL 만** 추가 (이미 있는 것은 건너뜀) |
| `--include-danger` | 이름에 금지 단어(`forbidden`)가 든 메뉴도 추가 (기본은 ⚠ 표시만 하고 제외) |

- `<a href="#" onclick="goPage('/emp.do')">` 처럼 href 가 없는 메뉴도 onclick 에서 경로를 뽑아낸다.
- **주소가 속성에 있는 프레임워크**(uxl/ub, 전자정부 등)도 지원한다. 예를 들어
  `<a href="#none" menuurl="VOC1001" menupath="VOC 업무>전체 VOC">` 면
  `menuurl` 의 화면ID + 규칙(`/screen/{}.ub`)으로 URL 을, `menupath` 로 `VOC 업무 > 전체 VOC` 라는 이름을 만든다.
  (이름에 `>` 가 든 속성 → 메뉴 경로, 이름에 `url/link/page` 가 든 속성 → 주소 순으로 본다)
- `<a href="#" data-menu-url="vocInterestList" data-menu-nm="나의 관심VOC">` 처럼 **슬러그가 속성에 있는 경우**도 잡는다
  (이름에 `url/link/page` 가 든 속성만 주소로 인정한다 — `data-click="showThirdMenu"` 같은 값에 속지 않기 위해).
- 로그아웃·다운로드·엑셀·팝업·외부 링크는 자동으로 뺀다.
- 이름에 **금지 단어(`forbidden`)가 든 메뉴는 버리지 않고 ⚠ 로 표시**하고 기본 선택에서만 뺀다.
  "결재 목록", "통보내역" 처럼 조회만 하면 되는 화면도 있기 때문이다(실제 위험은 화면 안의 버튼이고, 그건 실행할 때 막힌다).
  넣으려면 GUI 에서 체크하거나 CLI `--include-danger`, 그리고 시나리오 이름에 `(조회만)` 을 적어 두면 좋다.
- **초안일 뿐이다.** 목록의 데이터 행 링크(`홍길동` 같은 것), 위험 화면, 팝업 전용 화면을 지우고 이름을 `대메뉴 > 소메뉴` 로 다듬은 뒤 `expect` 를 채워야 쓸 만한 시나리오가 된다.

**조회 조건 입력 (`inputs`)** — 조회 화면은 기간·매장 같은 조건을 넣고 조회를 눌러야 데이터가 뜬다. 같은 이름의 입력란이 여러 화면에 있으면 공통값 한 번만 적어 두면 된다.
```json
"inputs": {
  "common": { "fromDate": "2026-01-01", "toDate": "2026-08-31", "storeCd": "1001" },
  "search": "a[title='Search'], #searchBtn a"
},
"menus": [
  { "name": "전체 VOC", "url": "/screen/VOC1001.ub", "inputs": { "storeCd": "2002" } },
  { "name": "안내팝업 관리", "url": "/screen/VOC1207.ub", "search": false }
]
```
| 위치 | 키 | 동작 |
|---|---|---|
| 최상위 `inputs.common` | `필드: 값` | 모든 메뉴에서 화면에 그 필드가 **보이면** 채운다. 없으면 조용히 건너뜀 |
| 최상위 `inputs.search` | 셀렉터 | 하나라도 채웠으면 이 버튼을 누르고 로딩을 기다린 뒤 검사 |
| 메뉴 `inputs` | `필드: 값` | 이 화면에서만. 공통값을 덮어씀. **필드가 없으면 ❌** (시나리오 오류로 잡기 위해) |
| 메뉴 `search` | `false` / 셀렉터 | 조회를 누르지 않음 / 이 화면 전용 조회 버튼 |

- 필드 키는 이름만 쓰면 `[name=이름]` → `#이름` 순으로 찾고, `#id`·`input[name=x]` 같은 CSS 셀렉터도 된다. iframe 안도 찾는다.
- `<select>` 는 option value → 없으면 표시 텍스트로, 체크박스는 `"true"/"false"`.
- 값에 `{{이름}}` 자리표시자를 쓰면 실행 시 입력받는다.
- 채운 값과 조회 클릭 여부는 보고서 "재현 경로"에 `입력: fromDate=2026-01-01, 조회 클릭` 으로 남는다.
- `detail` 로 상세에 들어갔다 목록으로 돌아올 때도 다시 입력·조회한다.
- `inputs.labels` 에 `{ "DT_START": "시작일" }` 처럼 설명을 두면 GUI 표·보고서 재현 경로에 함께 표시된다 (실행에는 영향 없음).
- GUI 편집 탭: "조회 조건 공통 입력값" 표(설명·필드·값) + 메뉴 행의 **입력값** 버튼 → 팝업. 팝업의 **[화면에서 필드 가져오기]** 는 로그인 후 그 화면을 실제로 열어 입력란(설명·종류·select 선택지·readonly 여부)을 읽어온다 → 값을 넣고 확인. 가져온 필드 목록은 메뉴의 `_fields` 에 저장돼 다음 편집 때 바로 보인다. 팝업 행의 **↑공통** 으로 공통 입력값에 올릴 수 있다.

**목록 → 상세 진입 (`detail`)** — 목록만 띄우고 끝내지 않고, 행을 클릭해 상세 화면까지 검사한다.
```json
{ "name": "사원관리", "url": "/emp/list.do", "expect": ["table"],
  "detail": { "selector": "table tbody tr td a", "rows": 2, "expect": ["#empForm"] } }
```
| 필드 | 의미 | 기본 |
|---|---|---|
| `selector` / `text` | 클릭할 행(또는 행 안의 링크) 셀렉터. 여러 개 매칭되면 위에서부터 | 필수 |
| `rows` | 몇 건까지 들어갈지 | 1 |
| `expect` | 상세 화면에서 꼭 보여야 하는 요소 | 없음 |
| `dblclick` | 더블클릭으로 여는 그리드 (jqGrid `tr.jqgrow` 등) | false |
| `popup` | 새 창으로 열리는 상세. 검사 후 자동으로 닫음 | false |
| `frame` | 목록이 iframe 안에 있으면 그 iframe 의 name | 없음 |
| `back` | 다음 행을 위해 목록으로 돌아가는 방법: `goto`(목록 URL 재진입, steps 재실행) / `back`(브라우저 뒤로) / `none`(같은 화면에서 계속 — 레이어/iframe 모달형. 검사 후 `close` 버튼 또는 Esc 로 닫음) | goto |
| `close` | `back: none` 일 때 모달 닫기 버튼 셀렉터 (기본: fancybox/jquery-ui/bootstrap 닫기 버튼 → 없으면 Esc) | 자동 |
| `waitFor` | 클릭 후 이 요소가 보일 때까지 대기 (AJAX 상세) | 없음 |
| `screenshot` | 상세 화면 증적 `true`/`false` (없으면 메뉴의 설정을 따름) | 메뉴 설정 |

- 결과는 `↳ 사원관리 상세 #1 (홍길동)` 처럼 **별도 행**으로 보고서에 실린다.
- 목록에 데이터가 없으면 ⚠️ "목록에 데이터가 없어 상세 조회 생략" 으로 기록 (실패 아님).
- 행 텍스트가 `forbidden` 과 매칭되면 클릭하지 않는다.
- GUI 편집 탭에서는 메뉴 행의 **상세 진입 셀렉터 / 건수** 열로 입력한다 (`dblclick`·`popup`·`frame` 은 JSON 직접 편집).

**버튼 동작 검사 (`actions`)** — 화면이 뜨는지만 보지 말고 **버튼을 눌러 동작까지** 확인한다. 버튼 하나가 결과표의 별도 행이 된다.
```json
{ "name": "전체 VOC", "url": "/screen/VOC1001.ub", "expect": ["#list"],
  "actions": [
    { "name": "조회", "click": "#searchBtn", "expect": ["#list"], "expectText": "총" },
    { "name": "매장검색 팝업", "click": "#btnVisitStrSerach", "expect": ["#storePop"] },
    { "name": "엑셀", "click": "#btnExcel", "skip": true }
  ] }
```
| 필드 | 의미 | 기본 |
|---|---|---|
| `name` | 결과에 `↳ <메뉴> · <이름>` 으로 찍힌다 (메뉴 안에서 중복 금지) | 필수 |
| `click` / `text` | 누를 버튼 셀렉터 또는 버튼 글자 | 필수 |
| `frame` | 버튼이 iframe 안이면 그 이름 (없으면 모든 프레임에서 찾는다) | 없음 |
| `expect` | 누른 뒤 보여야 하는 요소 | 없음 |
| `expectText` / `expectNotText` / `expectUrl` / `expectDialog` | 누른 뒤 나와야(없어야) 하는 글자 / URL / 알림 | 없음 |
| `popup` | 새 창으로 열리는 버튼 (검사 후 닫음) | false |
| `dblclick` · `wait` · `waitFor` · `loading` | 더블클릭 / 클릭 후 추가 대기(ms) / 기다릴 요소 / 로딩 표시 | - |
| `close` | 열린 레이어를 닫는 버튼 셀렉터. `false` 면 닫지 않음 (기본: 흔한 닫기 버튼 → 없으면 Esc) | 자동 |
| `back` | 다음 버튼을 위해 원래 화면으로: `goto`(메뉴 URL 재진입+조회 재입력) / `back` / `none` | URL이 바뀌었으면 goto |
| `skip` | 이 동작만 건너뜀 (지우지 않고 잠시 끌 때) | false |
| `allowForbidden` | 금지 버튼이지만 이 동작에서는 허용 (**사용자 확인 후에만**) | 없음 |

**적어 두지 않아도 자동으로 보는 것** (그래서 `actions` 만 넣어도 값이 있다):
- 버튼이 화면에 **없으면** ❌ (`버튼 없음: #btnX`) — 화면 개편으로 버튼이 사라진 것을 잡는다
- 누른 뒤 **JS 에러 / 서버 5xx / 에러 페이지** ❌
- **에러 알림**(`alert` 에 오류·실패·Exception) ❌ / 그 밖의 알림은 ⚠️ 기록
- **아무 반응이 없으면** ⚠️ `버튼을 눌렀지만 아무 반응이 없습니다` — 이동·팝업·서버 요청·DOM 변화·알림이 **전부** 없을 때. **죽은 버튼**을 잡는 검사다
- 화면 깨짐·빈 화면 등 기존 검사도 그대로 적용된다

**안전**: `forbidden`(삭제·발송·저장…)에 걸리는 버튼은 **누르지 않고** ❌ `금지 버튼 클릭 차단` 으로 남긴다. 실데이터를 바꾸는 흐름은 여기가 아니라 `crud`(⏺ 녹화)로 만든다.
버튼을 누른 뒤에는 **원래 화면으로 되돌린 다음** 다음 버튼을 누른다(레이어는 닫고, 화면이 바뀌었으면 메뉴 URL 재진입 + 조회 조건 재입력).

**클릭으로만 들어갈 수 있는 메뉴** (URL이 없거나 POST로 열리는 경우)
```json
{ "name": "급여관리(클릭 진입)", "steps": [
    { "action": "goto", "url": "/main.do" },
    { "action": "click", "text": "급여관리" },
    { "action": "waitForLoad" }
  ], "expect": ["table"] }
```

**iframe / 탭 구조 포털**: 포털이 iframe 안에 화면을 띄우는 구조여도 대개 **화면 URL로 직접 접근하면 동일하게 렌더링**된다. 그게 훨씬 안정적이므로 직접 URL을 쓰고, 정말 프레임 안에서만 되는 경우에만 `frame` 액션을 쓴다 (3장 참고).

**뺄 것**: 로그아웃 링크, 새 창(`window.open`) 으로만 열리는 팝업 메뉴, 소스가 없어 항상 에러나는 화면(알고 있다면), 발송/결제 화면. 대신 `_comment_menus` 에 왜 뺐는지 적어 둔다.

### 2-6. `crawl` — 링크 자동 수집 (선택)
메뉴 목록을 만들기 귀찮을 때, 메뉴 영역의 `<a>` 를 전부 긁어서 방문한다.
```json
"crawl": { "enabled": true, "startUrl": "/main", "selector": "#sidebar a, .gnb a", "exclude": ["logout", "download", "POP"], "maxPages": 100 }
```
- 같은 도메인 링크만, `javascript:` 와 `logout` 은 자동 제외
- `menus` 에 이미 있는 URL은 건너뜀 → 둘을 같이 써도 된다
- 메뉴 목록이 완전하면 `enabled: false` 로 두는 것이 재현성에 좋다

### 2-7. `crud` — 조작 흐름 (선택)
조회→등록→수정처럼 여러 스텝을 순서대로 수행한다. 한 흐름 = `name` + `steps`.
```json
"crud": [
  { "name": "사원 등록→조회", "steps": [
      { "action": "goto", "url": "/emp/list.do" },
      { "action": "click", "text": "등록" },
      { "action": "fill", "selector": "input[name=empName]", "value": "TEST_자동" },
      { "action": "click", "selector": "button:has-text('저장')" },
      { "action": "expectDialog", "text": "저장" },
      { "action": "goto", "url": "/emp/list.do" },
      { "action": "expectText", "text": "TEST_자동" }
  ]}
]
```
- 등록 테스트 데이터는 `TEST_` 같은 접두어를 붙여 나중에 찾아 지우기 쉽게 한다.
- `forbidden` 에 `저장` 이 들어 있으면 저장 버튼을 못 누른다. 등록 흐름에서만 허용하려면 그 흐름에 **`"allowForbidden": ["저장"]`** 을 넣는다 (다른 흐름과 메뉴 조회에는 여전히 금지 적용). `삭제`·`발송` 같은 것은 allow 하지 않는 것을 원칙으로.
- 흐름 하나가 실패해도 다음 흐름은 계속 실행된다.
- 실행 탭에서 **조회만 / CRUD만 / 둘 다** 를 고를 수 있으므로, 평소엔 "조회만"으로 안전하게 돌리고 필요할 때만 CRUD 를 켠다.

### 2-8. ⏺ 녹화 — 손으로 조작해서 스텝 만들기
CRUD 흐름이나 클릭 진입 메뉴의 스텝을 JSON 으로 직접 쓰는 대신, **브라우저에서 실제로 해 보면 그대로 기록**된다.

| 어디서 | 결과 |
|---|---|
| 편집 탭 CRUD 카드 **⏺ 녹화로 흐름 만들기** | `crud` 에 `{ name, steps }` 흐름 추가 |
| 편집 탭 메뉴 카드 **⏺ 녹화로 클릭 진입 메뉴 추가** | `menus` 에 `{ name, steps, expect }` 메뉴 추가 |
| 터미널 `run.bat record scenarios\프로젝트\x.json --url /emp/list.do --name "사원 등록" --append` | 파일의 `crud` 에 바로 추가 (`--append` 없으면 JSON 을 화면에 출력, `--no-login` 이면 로그인 생략) |

순서: 이름·시작 URL 입력 → **⏺ 녹화 시작** → 브라우저가 뜨고 로그인은 시나리오 설정대로 자동(기록 안 함) → 시작 URL 로 이동 → 손으로 조작 → 브라우저 상단 툴바 **■ 종료** → 스텝 확인/삭제/JSON 수정 → **추가** → 편집 탭 **저장**.

기록되는 동작과 변환 규칙:
| 조작 | 스텝 |
|---|---|
| 주소 이동(주소창 입력, JS 리다이렉트) | `goto` (baseUrl 기준 상대경로) |
| 클릭 뒤 페이지가 바뀜 | `click` + `waitForLoad` |
| 더블클릭 (그리드 행) | `dblclick` |
| 입력란 타이핑 | `fill` (칸을 떠날 때 최종값 하나만. 비밀번호 칸은 `{{password}}`) |
| `<select>` 변경 / 체크박스·라디오 | `select` / `check` |
| 입력란에서 Enter · Esc | `press` |
| iframe 안 클릭 | 앞에 `frame`(name 또는 iframe 셀렉터) 자동 삽입, 밖으로 나오면 `mainFrame` |
| 새 창이 열림 / 닫음 | 직전 `click` 에 `popup: true` / `closePopup` |
| alert / confirm | 자동 확인 후 `expectDialog` (메시지 앞 40자). **금지 단어(`forbidden`)가 든 confirm 은 취소**하고 `note` + `_warn` 으로 남긴다 — 아래 "금지 동작 허용" 참고 |
| 달력(datepicker)에서 날짜 선택 | 달력 안의 클릭(날짜·이전달·달력 아이콘)은 기록하지 않고, **바뀐 입력란 값을 `fill`** 로 (달이 바뀌어도 재생되도록). 달력 레이어 클래스가 특이하면 시나리오에 `"recorder": { "calendar": ".my-cal" }` |
| 마우스를 올려야 펼쳐지는 메뉴의 하위 항목 클릭 | 앞에 `hover`(상위 메뉴) 자동 삽입 |
| 파일 첨부 | `upload` — 브라우저는 파일 **이름만** 알려 주므로 `files` 를 절대경로로 고치거나 시나리오 폴더(또는 그 아래 `_files/`)에 파일을 둔다 |
| 목록 행(`tr`) 클릭 | 행 순번 대신 **그 행에만 있는 글자**(접수번호 등)로 `tr:has-text("…")`. "항상 첫 행"을 누르려는 흐름이면 `#list tr >> nth=1` 식으로 직접 고친다 |
| 툴바 **☑ 요소 확인** 후 클릭 | `expectVisible` (클릭 대신 검사만) |
| 툴바 **선택 텍스트 확인** (글자를 드래그한 뒤) | `expectText` |
| 툴바 **📸 캡처** | `screenshot` |

- 셀렉터 선택 순서: `#id`(동적으로 보이는 id 제외) → `tag[name=…]` → `title`/`aria-label`/`placeholder` 등 속성 → 20자 이하 고유 텍스트 `a:has-text("등록")` → CSS 경로. 재생이 안 되면 JSON 에서 그 스텝의 `selector` 만 고치면 된다.
- `_text`, `_note`, `_warn` 은 사람이 읽기 위한 참고 키(실행에 영향 없음). `_warn` 은 **금지 버튼을 눌렀다는 뜻** — 재생 시 차단되므로 그 흐름에 `allowForbidden` 을 넣을지 판단(추가 다이얼로그의 체크박스가 자동으로 넣어 줌).
- **금지 동작 허용**(녹화 시작 옆 체크박스 / 터미널 `--allow-forbidden`): 기본은 꺼짐 — 녹화 중 실수로 누른 버튼의 "삭제하시겠습니까?" 가 자동 확인되어 실데이터가 바뀌는 것을 막는다. 삭제·발송 흐름을 **일부러** 녹화할 때만 켠다. `_warn` 은 재생과 같은 기준(글자·title·value·aria-label·img alt·id·name)으로 붙으므로 글자 없는 아이콘 버튼도 녹화 시점에 경고된다.
- 녹화 중에는 다른 실행/필드 가져오기를 할 수 없다. 브라우저 창을 그냥 닫아도 녹화가 종료된다.
- 흔한 정리: 조회 조건을 넣고 조회를 누른 경우 `fill` 여러 개 + `click` 조회 + `waitForLoad` 로 나온다. 화면 로딩이 AJAX 면 `＋ 로딩 대기` 로 `waitForLoad` 를 끼워 넣는다.

## 3. 스텝 액션 레퍼런스

대상 지정은 `selector`(CSS/Playwright 셀렉터) · `text`(보이는 글자) · `role`+`name` 중 하나.

| action | 필드 | 설명 |
|---|---|---|
| `goto` | `url` | 페이지 이동 |
| `click` | 대상, `popup: true` | 클릭. 새 창이 열리는 버튼이면 `popup: true` → 이후 스텝은 새 창에서 실행 |
| `dblclick` | 대상 | 더블클릭 (그리드 행 → 상세) |
| `fill` | 대상, `value` | 입력란 값 채우기 (기존 값 지우고). readonly 입력란(달력)은 값을 직접 넣고 input/change 이벤트를 발생시킨다 |
| `hover` | 대상 | 마우스를 올림 (올려야 펼쳐지는 메뉴의 상위 항목) |
| `upload` | 대상(`input[type=file]`), `files` | 파일 첨부. `files` 는 절대경로, 또는 시나리오 폴더 · 그 아래 `_files/` · 도구 폴더 기준 상대경로 (배열 또는 문자열) |
| `type` | 대상, `value` | 한 글자씩 타이핑 (자동완성/키 이벤트 필요할 때) |
| `select` | 대상, `value` | `<select>` 값 선택 (option 의 value) |
| `check` | 대상, `value: true/false` | 체크박스 |
| `press` | (`selector`), `key` | 키 입력. `Enter`, `Tab`, `Escape`. 대상이 없으면 현재 포커스에 입력 |
| `frame` | `name` 또는 `selector` | iframe 안으로 들어감. 이후 스텝은 프레임 안에서 |
| `mainFrame` | | 프레임에서 나옴 |
| `closePopup` | | 팝업 창 닫고 원래 창으로 |
| `wait` | `ms` | 그냥 대기 |
| `waitFor` | 대상, `state` | 요소가 `visible`(기본)/`hidden` 될 때까지 대기 |
| `waitForLoad` | `state` | `networkidle`(기본)/`load`/`domcontentloaded` 까지 대기. AJAX 화면은 클릭 뒤에 넣는다 |
| `expectVisible` | 대상 | 보여야 함 |
| `expectText` / `expectNotText` | `text` | 본문에 있어야/없어야 함 |
| `expectUrl` | `contains` | 현재 URL에 포함 |
| `expectDialog` | `text`, (`timeout`) | alert/confirm 메시지에 포함. **아직 안 떴으면 `timeout`(기본 시나리오 timeout)까지 기다린다** — 저장 → AJAX → 알림처럼 늦게 뜨는 경우. 확인한 알림은 소비되므로 같은 문구를 두 번 검사하면 두 번째는 새로 뜬 알림이어야 한다 |
| `screenshot` | `name` | 이 시점 화면 캡처 (증적에 추가) |
| `eval` | `script` | 페이지에서 JS 실행 (최후 수단) |

**셀렉터 팁**
- id 가 있으면 `#id` 가 제일 안정적
- 텍스트로: `"text": "등록"` 또는 `"selector": "button:has-text('저장')"`
- 공통 버튼 마크업이 `<span id="saveBtn"><a title="Save">` 식이면 `#saveBtn a` 또는 `a[title='Save']`
- 여러 후보를 한 번에: `"selector": "a[title='Search'], #searchBtn a"` (먼저 찾히는 것 사용)
- 그리드 첫 행: `#grid tr >> nth=1` (jqGrid 는 0번 행이 헤더용 빈 행인 경우 있음)

**iframe 예**
```json
{ "action": "goto", "url": "/portal.do" },
{ "action": "frame", "name": "contentFrame" },
{ "action": "click", "text": "조회" },
{ "action": "mainFrame" }
```
프레임 이름은 F12 → Elements 에서 `<iframe name="...">` 을 본다. name 이 없으면 `"selector": "#tabs iframe"`.

**팝업 예**
```json
{ "action": "click", "text": "우편번호 찾기", "popup": true },
{ "action": "fill", "selector": "input[name=keyword]", "value": "역삼" },
{ "action": "press", "key": "Enter" },
{ "action": "closePopup" }
```

   - `핵심 요소 없음` 만 뜨고 화면은 정상 → `expect` 셀렉터가 틀린 것 (스크린샷으로 확인)

   - `빈 화면` ⚠️ → 권한 없음 또는 AJAX 로딩 전 캡처. `timeout` 을 늘리거나 `expect` 로 로딩 완료 요소를 지정
   - `콘솔 에러` ⚠️ → jquery-migrate 경고 같은 노이즈일 수 있음. 반복되면 무시 판단 후 메모

7-1. [ ] 목록 화면에는 `detail` 을 붙여 상세 화면까지 들어가 보도록 (2-5 참고)

12. [ ] 파일을 사내 공유 위치에 두고 git 에는 올리지 않는다 (비밀번호 포함)

## 4-2. 두 번째 실행부터 — 비교 / 실패건만 재실행 / 매트릭스

한 번 돌려서 ❌ 목록을 만들었으면, 그 다음부터는 **"이번에 새로 깨진 게 있나"** 만 보면 된다.

### 직전 실행과 비교 (자동)
같은 폴더에 있는 **같은 시나리오의 가장 최근 증적**을 기준으로 비교해서 보고서 맨 위에 표시한다.

```
직전 실행 대비   🆕 신규 실패 2   ✨ 해결 3   ➖ 그대로 실패 16
기준: 스타벅스_VOC-20260827-101500 · 2026-08-27 10:15 (정상 40 / 실패 19 / 주의 2)
```

표에 **변화** 칸이 생기고(🆕 신규 실패 / ✨ 해결 / ✚ 신규 항목 / ➖ 이전에도 실패), 신규 실패 행은 진한 빨강으로 표시된다.

- 끄기: GUI 실행 탭 "이전 결과와 비교" 체크 해제 / CLI `--no-compare`
- 기준 직접 지정: `--compare reports/스타벅스/01_메뉴회귀/스타벅스_VOC-20260827-101500`
- 기준에서 자동 제외되는 실행: 로그인 실패로 끝난 실행, 일부만 돌린 실행(실패건만 재실행·이름 필터)
- 상세 항목(`↳ … 상세 #1 (행 텍스트)`)은 괄호 안 행 텍스트가 매번 달라지므로 그 부분을 떼고 비교한다

### 실패건만 재실행
직전 실행에서 ❌·⚠️ 였던 항목만 다시 돌린다. 109개 메뉴 중 18개만 → 실행 시간이 1/6로 준다.

- GUI 실행 탭 "실패건만 재실행" 체크 후 ▶ 실행 (기준 = 가장 최근 증적)
- GUI 증적 탭의 각 줄 **↻ 실패만 재실행** (그 실행을 기준으로)
- CLI `run.bat scenarios\스타벅스\01_메뉴회귀\starbucks-voc.json --rerun-failed`
- 폴더(프로젝트) 일괄에도 적용된다 — 실패가 없던 시나리오는 통째로 건너뛴다
- 상세(`↳ …`) 가 실패했으면 그 **부모 메뉴**를 다시 실행한다. 로그인 실패는 대상에서 뺀다(어차피 다시 로그인한다)

### 시나리오별 매트릭스 (일괄 실행)
폴더/프로젝트를 일괄 실행했을 때 여러 시나리오가 같은 항목 이름을 공유하면, 합산 보고서에
**행 = 항목, 열 = 시나리오(역할)** 표가 자동으로 붙는다. 권한 테스트 결과를 한 장으로 보여 줄 때 쓴다.

| 항목 | P01 시스템관리자 | P05 VOC관리자 | P24 일반사용자 |
|---|---|---|---|
| VOC 등록 | ✅ | ✅ | 🚫 |
| 통계 | ✅ | ✅ | · |

- 🚫 는 시나리오의 `"blocked": ["권한이 없", "접근 권한", "403"]` 정규식에 걸린 증상 → "권한으로 막힌 것"으로 구분해서 표시
  (상태 자체는 그대로 ❌ 로 집계된다. 판단 근거만 보여 주는 표시)
- `·` 는 그 시나리오에 없는 항목, 겹치는 항목이 2개 미만이면 표를 만들지 않는다

## 4-3. 오탐 줄이기 · 증적 다듬기 (재시도 / 소요시간 / 깨진 화면 / 분류 / CSV)

### `retry` — 불안정(flaky) 실패 걸러내기
서버가 잠깐 느리거나 AJAX 가 덜 끝나서 나는 **실제 버그가 아닌 실패**를 줄인다.
실패하면 그 화면만 다시 실행하고, 나중 시도에서 정상이면 ❌ 대신 **⚠️ 불안정(flaky)** 으로 기록한다(증적은 실패 시점 화면을 남긴다).

```json
{ "retry": 1,                                  // 시나리오 전체 기본값
  "menus": [ { "name": "느린통계", "url": "/stat", "retry": 2 },   // 화면별로 덮어쓰기
             { "name": "에러메뉴", "url": "/err", "retry": 0 } ] } // 이 화면은 재시도 안 함
```
- CRUD 흐름은 데이터를 만들 수 있으므로 **시나리오 기본값을 따르지 않는다.** 재시도가 필요하면 그 흐름에 `"retry": 1` 을 직접 넣는다(조회 전용 흐름에만 권장).
- 보고서 총평의 `불안정(flaky) N` 이 계속 늘어나면 그 화면은 진짜로 불안정한 것이니 개발팀에 알린다.

### 전체 설정 (`config.json`) — 순회 속도 등 공통 기본값
프로젝트 루트의 `config.json` 은 **모든 시나리오에 적용되는 기본값**이다. GUI 헤더의 **⚙ 설정** 버튼(또는 파일 직접 편집)으로 바꾼다.
**시나리오에서 따로 정한 값이 있으면 그 값이 우선**한다 — `config.json` 은 "안 정한 것"만 채운다.

| 키 | 뜻 |
|---|---|
| `speed` | 순회 속도 프리셋: `아주 느림`(step 1500·slowMo 200) / `느림`(1000·120) / `보통`(500·0) / `빠름`(200·0) |
| `retries` | 로그인 재시도 기본 횟수 (계정 잠금 정책이 있으면 1~2 로 낮춘다) |
| `timeout` `expectTimeout` | 요소 대기·핵심 요소 대기 기본(ms). 사내 서버가 느리면 전역으로 올린다 |
| `headless` | 브라우저 창 숨김 기본. 보안 프로그램이 headless 를 봇으로 잘 잡으니 반입 환경은 `false`(창 보이게) 권장 |
| `screenshot` | 증적 캡처 기본 `all`/`fail`/`none`. `fail`(실패만) 로 두면 개인정보 노출을 줄인다 |
| `compare` | 직전 실행 비교 기본 on/off |
| `checks` | 깨진 화면 검사 `{ images, layout }` 기본 |
| `stepDelay` `slowMo` `slowMs` `emptyWait` | 속도 프리셋 대신 개별 지정 (⚙ 설정의 "고급") |

```json
{ "speed": "느림", "retries": 2, "headless": false, "screenshot": "fail" }
```
- **순회 속도를 느리게** 하면 짧은 시간에 여러 메뉴를 도는 것이 WAF·IPS 에 스캐닝으로 오인될 확률이 낮아진다. 보안이 엄격한 곳은 `느림` 이상을 권장.
- 개별 시나리오만 다르게 하려면 그 시나리오에 `stepDelay` 등을 직접 넣으면 된다(그 값이 이긴다).
- 자체 검증은 `--no-config`(CLI) / `WWT_NO_CONFIG=1`(env) 로 전역 설정을 무시하고 돌린다.

### 인터페이스 목업 (`mocks`) — 외부 호출을 실제로 안 타고 지정 값으로
대상 시스템이 부르는 **외부 서비스/인터페이스**가 테스트 환경에서 연동이 안 될 때, 그 호출을 실제로 보내지 않고 **지정한 응답으로 바로** 돌려준다(Playwright `route` 로 브라우저 요청을 가로챔).
```json
{ "mocks": [
    { "url": "/api/creditRate", "json": { "code": "0000", "rate": 4.5 } },
    { "url": "**/legacy/**", "status": 500, "body": "down" },
    { "url": "re:https?://ext\\.bank/.*", "abort": true }
] }
```
| 필드 | 뜻 |
|---|---|
| `url` | 매칭. 그냥 문자열 = **부분일치** · `*`/`**` 포함 = 글로벌 패턴 · `re:` 접두 = 정규식 |
| `status` | 응답 코드(기본 200) |
| `json` / `body` | 응답 본문. `json` 은 객체(자동 직렬화), `body` 는 문자열. 안에서 `{{변수}}`·동적 토큰 사용 가능 |
| `method` | 이 메서드일 때만(GET/POST…). 생략하면 전부 |
| `contentType` `headers` | 응답 헤더 (교차 출처 CORS 는 자동 허용) |
| `abort` | `true` 면 호출 자체를 차단(에러) |
| `delayMs` | 응답 지연(ms) — 느린 인터페이스 흉내 |
- 로그인 포함 실행 전 구간에 적용된다. 편집 화면 **"인터페이스 목업"** 카드에 JSON 배열로 넣는다.
- 이건 `inputs`/`vars`(내가 화면에 넣는 값)와 **다르다** — 그건 입력 데이터, 이건 대상이 부르는 외부 호출의 응답을 바꾸는 것.
- **주의**: 이 `mocks` 는 **브라우저(화면)가 직접 부르는** fetch/XHR 만 잡는다. **백엔드 서버가 부르는 외부 연동**은 아래 서버 stub 을 쓴다.

### 서버 stub (`stubServer`) — 백엔드가 부르는 외부 연동 목업 (프로젝트 단위 on/off)
대상 앱의 **백엔드가 부르는 외부 서비스**(브라우저를 안 거침)를 목업하려면, 실제 HTTP stub 서버를 띄우고 앱이 그걸 보게 한다. **프로젝트 설정(🔧)** 에 두어 환경별로 켜고 끈다 — **로컬=목업 ON / 개발·운영=실제 OFF**.
```json
{ "stubServer": { "enabled": true, "port": 9900, "routes": [
    { "path": "/api/creditRate", "json": { "code": "0000", "rate": 4.5 } },
    { "path": "/api/send", "method": "POST", "status": 200, "body": "OK" },
    { "path": "re:/legacy/.*", "status": 500 }
] } }
```
- `enabled: false` 로 두면(개발/운영 프로젝트) stub 을 안 띄우고 실제 외부를 탄다. 라우트 문법은 `mocks` 와 같다(path 부분일치/`*`/`re:`, json/body/status/method/delayMs, `{{변수}}`·동적 토큰).
- 실행할 때 자동으로 `:port` 에 떠서 시나리오가 끝나면 내려간다. **단독으로 계속 띄우려면** `run.bat stub scenarios\<프로젝트>\<시나리오>.json` (앱을 붙여 수동 테스트할 때, Ctrl+C 종료).
- **대상 앱이 이 stub 을 보도록** 외부 연동 주소를 설정 변경(`application.properties` 등)하거나 hosts 로 돌리는 건 환경 세팅이라 직접 해야 한다(도구가 백엔드 설정까지 바꾸진 못함).

### 테스트 데이터 (`vars`) + 동적 토큰 — 목업 값 재사용
등록·검색에 넣을 목업 값을 `vars` 에 정의하고, 다른 곳에서 `{{이름}}` 으로 참조한다. CRUD 흐름·조회 조건(`inputs`)·메뉴 입력값 어디서나 쓸 수 있다.
```json
{ "vars": { "custName": "테스트고객", "phone": "010-0000-0000" },
  "crud": [ { "name": "등록", "steps": [
    { "action": "fill", "selector": "#custNm", "value": "{{custName}}-{{seq}}" },
    { "action": "fill", "selector": "#tel", "value": "{{phone}}" } ] } ] }
```
- **동적 토큰**(실행마다 값이 달라짐 — 같은 값 재등록으로 실패하는 중복키를 피할 때):
  `{{today}}`(2026-08-29) · `{{now}}`(20260829_143022) · `{{time}}`(143022) · `{{ts}}`(epoch) ·
  `{{rand}}`/`{{rand6}}`(6자리) · `{{rand4}}`(4자리) · `{{uuid}}`(8자리) · `{{seq}}`(1,2,3… 쓸 때마다 증가).
  한 실행 안에서 `{{now}}`·`{{uuid}}` 등은 **같은 값**(한 레코드의 필드끼리 일관), `{{seq}}` 만 매번 증가.
- **우선순위**: 실행 시 입력(`{{password}}` 처럼 vars 에 없는 이름 → 실행할 때 팝업) > `vars` > 동적 토큰.
- 비밀번호·주민번호처럼 **파일에 남기면 안 되는 값**은 `vars` 에 넣지 말고 이름만 `{{ssn}}` 처럼 쓰면 실행 때 물어본다(파일 미저장).
- 편집 화면 **"테스트 데이터 (변수)"** 카드에서 이름·값을 넣는다.

### 프로젝트 공통 설정 (`_project.json`) — 접속 URL·브라우저·로그인·stub·세션 재사용 상속
같은 사이트의 여러 시나리오가 **접속 URL·브라우저·로그인·서버 stub·로그인 세션 재사용**을 반복 입력하지 않도록, 프로젝트 단위로 한 번만 정해 둔다.
파일: `scenarios/<프로젝트>/_project.json` (예: `{ "baseUrl": "...", "browser": { "channel": "chrome" }, "login": { ... }, "reuseSession": true }`).
상속되는 키: `baseUrl` `browser` `login` `stubServer` `reuseSession`.

- 만들기: 한 시나리오에서 접속·로그인을 입력한 뒤 편집 탭의 **📌 프로젝트 공통으로** 버튼을 누르면 저장된다.
- 쓰기: 각 시나리오 편집 폼의 접속 URL·브라우저·로그인 옆 **"프로젝트 상속"** 체크박스.
  - 체크 = 프로젝트 공통값을 쓴다(파일에 저장 안 함, 값은 잠겨서 표시). 프로젝트 설정을 바꾸면 상속한 시나리오 전부에 반영.
  - 해제 = 이 시나리오에서 직접 지정(그 값만 파일에 저장).
- 우선순위: **시나리오 자신 > 프로젝트 공통(_project.json) > extends(_공통)**. 즉 시나리오가 **자기 파일에** baseUrl/브라우저/로그인을 직접 정하지 않았으면, extends 로 상속한 값이 있어도 **프로젝트 설정이 우선**한다. → 🔧 프로젝트 설정을 바꾸면 상속받는 시나리오 전부가 그 값으로 돈다.
  - (그래서 extends 부모 `_공통.json` 에 baseUrl 이 있어도 프로젝트 설정이 이긴다. 특정 시나리오만 다르게 하려면 그 시나리오 파일에 직접 baseUrl 을 넣으면 그게 최우선.)
- 프로젝트에 로그인이 있는데 이 시나리오만 로그인 없이 돌리려면, 로그인 "사용"을 끄고 상속을 해제하면 된다(자동으로 상속을 막는다).

### 로그인 세션 재사용 (`reuseSession`) — 프로젝트 단위로 켜는 것을 권장
최초 로그인 뒤 세션(쿠키·스토리지)을 `.sessions/` 에 저장해 **다음 실행·시나리오에서 재사용**한다. 세션이 만료됐으면 자동으로 다시 로그인한다.
- **효과**: 일괄 실행(같은 접속 URL·같은 아이디)에서 로그인을 한 번만 → 빠르고, 로그인 반복이 줄어 계정 잠금·과도한 로그인 부하를 피한다.
- **어디서 켜나 (권장 순서)**
  1. **🔧 프로젝트 설정 → "로그인 세션 재사용"** — 그 프로젝트의 모든 시나리오가 **기본으로 상속**한다. 사이트 단위 설정이라 여기가 제일 알맞다.
  2. ⚙ 전체 설정 — 모든 프로젝트의 기본값.
  3. 시나리오 편집 폼의 **로그인 세션 재사용** 3단 선택 — `기본 (프로젝트 상속)` / `사용` / `사용 안 함`.
     - **기본**이면 시나리오 파일에 값을 아예 쓰지 않는다 → 프로젝트 설정을 바꾸면 그대로 따라간다(옆에 `→ 프로젝트: 사용` 처럼 지금 적용되는 값이 표시된다).
     - 특정 시나리오만 다르게 하려면 `사용` / `사용 안 함` 을 고른다(그 시나리오 파일에만 저장되고, 프로젝트보다 우선).
- 우선순위: **시나리오 자신 > 프로젝트(_project.json) > extends(_공통) > 전체 설정(config.json)**.
- 세션은 `접속 URL + 로그인 아이디` 기준으로 공유된다(계정이 다르면 따로 — 권한 페르소나 시나리오도 안전). `switchUser` 로 바꾼 계정은 세션에 저장하지 않는다.
- `.sessions/` 는 쿠키를 담으므로 로컬 전용(반입 zip 에 포함 안 됨). 기본은 꺼져 있다.

### `slowMs` — 느린 화면
모든 항목의 소요시간(초)을 재서 보고서 표의 `초` 칸과 "오래 걸린 화면 TOP 5" 에 남긴다.
`slowMs` 를 정하면 그 시간을 넘는 화면은 ⚠️ 로 잡는다. 직전 실행과 비교해 **2배 이상 + 1초 이상 느려진 화면**은 `🐢 느려짐` 으로 따로 표시된다.

### `checks` — 깨진 화면
| 검사 | 기본 | 내용 |
|---|---|---|
| `images` | 켬 | 화면에 보이는 `<img>` 중 로드 실패(naturalWidth 0)한 것 → ⚠️ `이미지 로드 실패 N개` |
| `layout` | **끔** | 내용이 화면보다 넓어 가로 스크롤이 생기면 → ⚠️ `가로 스크롤 발생` |

`layout` 은 사이트에 따라 정상인데도 계속 걸리는 경우가 있어 기본은 꺼져 있다(`"checks": { "layout": true }` 로 켠다).
특정 이미지(광고·트래킹 픽셀 등)는 `ignore.resources` 정규식으로 제외한다.

### 증상 분류(triage) — 규칙 기반 1차 분류
❌·⚠️ 항목마다 증상 문구를 보고 자동으로 분류를 붙인다. **AI 가 아니라 정해진 규칙**이므로 최종 판단은 사람이 한다.

| 분류 | 무엇을 봐야 하나 |
|---|---|
| `서버 버그` | HTTP 5xx, **AJAX 5xx(`서버 오류 응답`)**, 에러 페이지, 스택트레이스, JS 예외, 업무오류 응답 → **개발팀** |
| `권한/세션` | 로그인 화면으로 되돌아감, 401/403 → 계정 권한 또는 세션 설정 |
| `안전장치 차단` | `forbidden` 버튼을 눌러서 막힌 것, 금지 문구 확인창을 취소한 것 → 시나리오 의도대로 동작한 것 |
| `시나리오 오류 의심` | 핵심 요소 없음, 입력 필드 없음, 셀렉터 타임아웃 → **시나리오 JSON 을 고칠 것** |
| `데이터 부족` | 목록 0건이라 상세 생략, 빈 화면 → 테스트 데이터 문제 |
| `화면 깨짐 의심` / `느림` / `불안정(flaky)` | 위 검사에서 나온 것 |
| `환경 노이즈 의심` | 콘솔 에러·리소스 404 만 있는 경우 → `ignore` 후보 |

### 느린 화면(무거운 쿼리·늦게 그려지는 그리드) 대응
"화면은 결국 뜨는데 우리 도구가 먼저 포기해서" ❌ 가 나오는 경우를 막는 장치들이다.

| 키 | 위치 | 뜻 |
|---|---|---|
| `timeout` | 시나리오 / **메뉴·흐름별** | 요소를 기다리는 기본 시간(ms). 무거운 통계 화면만 `"timeout": 30000` 처럼 따로 준다 |
| `expectTimeout` | 시나리오 / 메뉴별 | **핵심 요소(expect)를 기다리는 시간.** 기본은 `timeout` 의 절반(최소 3초). 그리드가 10초 뒤에 그려지면 `"expectTimeout": 15000` |
| `loading` | 시나리오 / 메뉴별 | 로딩 표시 셀렉터(`#loading`, `.spinner`, 딤 레이어 등). **이게 사라질 때까지 기다린 뒤** 화면을 판정한다 |
| `waitFor` | 메뉴별 | 이 요소가 나타날 때까지 기다린다(안 나타나도 진행하고 로그만 남김). 조회 후 그리드 첫 행 등 |
| `retry` | 시나리오 / 메뉴별 | 재시도할 때 **대기 시간을 회차만큼 배로 늘린다**(2차 = 2배). 서버가 잠깐 느렸던 경우를 구제 |
| `emptyWait` | 시나리오 | 본문이 비어 보일 때 **다시 읽어 보는 시간**(ms, 기본 1500). 목록 자리에 상세를 다시 그리는 화면처럼 검사 순간에만 잠깐 비는 경우의 "빈 화면" 오탐을 막는다. 정상 화면은 첫 읽기에 통과하므로 느려지지 않는다 |

```json
{ "timeout": 10000, "expectTimeout": 8000, "loading": "#loading, .ui-widget-overlay", "retry": 1,
  "menus": [
    { "name": "월별 통계", "url": "/stat/month", "expect": ["#grid"],
      "timeout": 40000, "expectTimeout": 30000, "waitFor": "#grid tbody tr" }
  ] }
```
- 실패 메시지에 기다린 시간이 함께 남는다: `핵심 요소 없음: #grid (5초 대기)` → 이 숫자를 보고 늘릴지 판단한다.
- 늘려서 성공했더라도 `slowMs` 를 넘으면 ⚠️ **느림**으로 기록되므로 "되긴 되는데 느린 화면" 목록이 따로 남는다.

### 개인정보 가림 (`mask`)
스크린샷을 찍기 **직전에** 지정한 요소를 회색으로 덮는다(캡처 후 원상복구). 고객 이름·연락처·주민번호가 증적에 그대로 남는 것을 막는다.

```json
"mask": ["#custNm", "td.phone", ".ssn", "#grid td:nth-child(3)"],
"maskColor": "#9aa3af",
"menus": [ { "name": "고객조회", "url": "/cust", "mask": ["#detail .addr"] } ]
```
- 시나리오 공통 `mask` + 항목별 `mask` 를 **합쳐서** 적용한다. iframe 안의 요소도 가려진다.
- 화면 구조는 그대로 남기 때문에 `"screenshot": false` 로 화면 전체를 포기하는 것보다 증적 가치가 높다.
- 그리드 컬럼 단위(`td:nth-child(3)`)로 지정하면 목록에서 이름 열만 가릴 수 있다.

### 계정 전환 (`switchUser`)
결재 상신 → 승인 → 회신처럼 **여러 역할이 이어지는 업무 흐름**을 시나리오 하나로 검증한다.
로그아웃(쿠키 정리) 후 같은 로그인 스텝을 다른 아이디로 다시 실행하며, 성공 판정·재시도는 로그인과 똑같이 동작한다.

```json
"login": { "url": "/login", "userField": "#userId", "logoutUrl": "/logout", "steps": [ ... ], "success": { ... } },
"crud": [{
  "name": "제도개선 상신 → 승인 → 확인",
  "steps": [
    { "action": "goto", "url": "/improvement/regList" },
    { "action": "note", "text": "여기까지는 담당자(로그인 계정)" },
    { "action": "switchUser", "user": "test05", "url": "/aprvBas" },
    { "action": "expectText", "text": "결재함" },
    { "action": "switchUser", "user": "{{userId}}", "password": "{{password}}" }
  ]
}]
```
| 필드 | 뜻 |
|---|---|
| `user` | 바꿀 아이디 (자리표시자 `{{...}}` 사용 가능) |
| `password` | 생략하면 원래 로그인 스텝의 비밀번호를 그대로 쓴다 (계정마다 다르면 `{{pw05}}` 처럼) |
| `url` | 전환 후 이동할 화면 (선택) |
| `logout` | 로그아웃 주소 (선택, 없으면 `login.logoutUrl` → 쿠키 정리) |
- 아이디 칸은 `login.userField`(셀렉터)로 지정하고, 없으면 로그인 스텝의 **첫 번째 입력**을 아이디로 본다.
- 보고서의 재현 경로에 `3. 계정 전환 → test05` 로 남는다.

## 5. 실제 예제 해설 — `scenarios/starbucks-voc.json`

| 항목 | 값 | 어디서 찾았나 |
|---|---|---|
| baseUrl | `http://localhost:8080/voc` | `server.xml` 포트 8080, `build.gradle` 의 `voc.war` → `/voc` |
| 로그인 URL | `/screen/BCO0001.ub` | `index.jsp` 가 이리로 redirect |
| 아이디/비번 | `#userid`, `#userpw` | `BCO0001.jsp` 의 `<input id="userid">` |
| 로그인 버튼 | `#login` | `<div class="login-btn" id="login">` — button 태그가 아님 |
| 로그인 후 처리 | `goto /screen/POR0001.ub` 추가 | `loginSuccess.jsp` 가 컨텍스트 빠진 경로로 보내는 버그가 있어 직접 이동 |
| success | `urlContains POR0001` + `selector #menu` | 포털 메뉴 영역 id |
| 메뉴 61개 | `/screen/{화면ID}.ub` | `scripts/menu/menu_dump.csv` (메뉴 테이블 덤프, STATUS=A) + 화면ID→URL 규칙 |
| 제외 | POP0007, APP0003, EXP8001 | 새 창 팝업 / SMS 발송 / 소스 없음 |
| forbidden | 삭제·발송·강제실행·상신·승인·반려·마감·저장 | 프로젝트 CLAUDE.md "절대 하지 말 것" + JSP 버튼 검색 |
| expect | `table.ui-jqgrid-btable` | 이 프로젝트 그리드(jqGrid) 공통 클래스 |

같은 프레임워크(ub/uxl) 를 쓰는 다른 프로젝트라면 이 파일을 복사해서 `baseUrl`, 계정, 메뉴 표만 바꾸면 된다.

## 6. 자주 겪는 문제

| 증상 | 원인/해결 |
|---|---|
| `로그인 실패: URL에 "..." 없음` | 로그인은 됐는데 이동 경로가 예상과 다름. 브라우저에서 로그인 후 주소를 보고 `success` 수정 |
| 로그인 버튼 클릭이 안 먹음 | 버튼이 `<div>`/`<img>` → 그 요소 id로. 또는 `press Enter` 를 비밀번호 칸에 |
| 모든 메뉴가 로그인 화면으로 감 | 세션 유지 안 됨. `success` 를 통과했는지, 로그인 스텝 뒤 `waitForLoad` 가 있는지 확인 |
| 한글 파일명/이름 깨짐 | JSON 파일이 UTF-8 이 아님 |
| `Timeout ... waiting for selector` | 셀렉터 오타, 또는 iframe 안에 있음(`frame` 액션 필요), 또는 로딩이 느림(`timeout` 증가) |
| 실행은 되는데 ⚠️ 콘솔 에러가 모든 화면에 뜸 | 공통 JS 경고. 정말 문제인지 한 번만 확인하고 보고서 읽을 때 무시 |
| Chrome 못 찾음 | `browser.channel` 삭제 후 `npx playwright install chromium` |
