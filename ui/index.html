실행 이력

실행 시각시나리오전체정상주의실패증적

사용 순서

  1. 왼쪽 ＋ 프로젝트/폴더 로 프로젝트를 만들고(예: 스타벅스VOC/조회), ＋ 새 시나리오 → 이름, 접속 URL, 로그인 정보, 메뉴 목록 입력 → 저장 위치 선택 → 저장
  2. 실행 탭: 왼쪽에서 시나리오 하나를 고르면 그것만, 프로젝트나 폴더를 고르면 그 아래 전부 일괄 실행(각 폴더의 ▶ 버튼도 같음). 범위(조회/CRUD) 선택 → ▶ 실행
  3. 끝나면 증적 탭에서 보고서(HTML) 열기. 일괄 실행은 합산 보고서 + 시나리오별 폴더가 한 폴더에 들어감. 폴더째 복사하면 제출용 증적

각 화면에서 확인: HTTP 4xx/5xx · 톰캣/스프링 에러 페이지 · JS 예외 · 콘솔 에러 · 빈 화면 · 필수 요소 유무. 금지 버튼은 절대 누르지 않음.

두 번째 실행부터 — 달라진 것만 보기

  • 이전 결과와 비교(기본 켬): 보고서 맨 위에 🆕 신규 실패 2 / ✨ 해결 3 / ➖ 그대로 실패 16 과 표의 "변화" 칸이 생깁니다. 기준은 같은 폴더에 있는 같은 시나리오의 가장 최근 증적 (로그인 실패로 끝난 실행, 일부만 돌린 실행은 기준에서 자동 제외).
  • 실패건만 재실행: 직전 실행에서 ❌·⚠️ 였던 항목만 다시 돌립니다. 증적 탭의 ↻ 실패만 재실행 은 그 실행을 기준으로 합니다. 일괄 실행이면 실패가 없던 시나리오는 통째로 건너뜁니다.
  • 시나리오별 매트릭스: 폴더/프로젝트를 일괄 실행했을 때 여러 시나리오에 같은 항목이 있으면 합산 보고서에 행=항목 / 열=시나리오(역할) 표가 붙습니다. 권한 테스트 결과를 한 장으로 낼 때 씁니다.
  • 오탐 줄이기(편집 탭 "안정성 · 성능"): 재시도를 1 이상으로 두면 실패한 화면만 다시 실행해서 두 번째에 정상이면 ❌ 가 아니라 ⚠️ 불안정(flaky) 으로 남깁니다(증적은 실패 시점 화면). 느린 화면 기준을 정하면 그 시간을 넘는 화면이 ⚠️ 로 잡히고, 모든 화면의 소요시간이 보고서에 남습니다. 깨진 이미지 / 가로 스크롤 검사도 여기서 켭니다.
  • 증상 분류 · 결함 CSV: ❌·⚠️ 마다 서버 버그 / 권한·세션 / 시나리오 오류 의심 / 데이터 부족 / 환경 노이즈 같은 1차 분류가 붙습니다(규칙 기반이라 최종 판단은 사람이). 증적 폴더의 defects.csv 는 결함만 뽑은 엑셀용 목록입니다.
  • 🔗 공통 설정 상속: 계정만 다른 시나리오가 여러 개면 공통 부분을 _공통.json 에 두고 각 파일에 "extends": "_공통.json" (JSON 직접 편집)을 넣으세요. 메뉴가 늘어도 공통 파일 한 곳만 고치면 됩니다. 상속 시나리오를 편집 탭에서 열면 상속값까지 합쳐 보이고, 저장하면 다른 값만 그 파일에 남습니다.

화면·보고서 다루기

  • 왼쪽 목록은 헤더의 ☰ 또는 Ctrl+B 로 접고, 경계선을 드래그해 화면 절반까지 넓힐 수 있습니다(더블클릭 = 기본 폭). 폭·접힘은 기억됩니다.
  • 보고서 위쪽 전체 / 정상 / 실패 / 주의 / 🆕 신규 실패 칸을 누르면 그 항목만 보입니다. 스크린샷 영역도 같이 걸러집니다.
  • 결함 CSV 는 엑셀 등 기본 프로그램으로 바로 열립니다(앱 창에서는 브라우저 다운로드가 동작하지 않습니다).
  • 편집 탭 ✓ 검사 로 저장 전에 실수를 확인하세요 — 메뉴 이름 중복(비교·재실행이 엉킵니다), 필수값 누락, 모르는 동작, 평문 비밀번호 등.

느린 화면 / 개인정보 / 계정 전환

  • 느린 화면: 조회가 오래 걸려 ❌ 가 나오면 편집 탭에서 요소 대기(ms) 를 늘리거나, JSON 직접 편집에서 메뉴에 "timeout"·"expectTimeout"·"loading"(로딩 표시 셀렉터)·"waitFor" 를 넣으세요. 실패 메시지에 몇 초 기다렸는지가 함께 나옵니다. 재시도할 때는 대기 시간이 회차만큼 늘어납니다.
  • 개인정보 가림: 편집 탭 개인정보 가림 에 #custNm, td.phone 처럼 넣으면 스크린샷에서 그 부분만 회색으로 덮습니다(iframe 안도).
  • 계정 전환: CRUD 흐름 스텝에 { "action": "switchUser", "user": "test05" } 를 넣으면 로그아웃 후 그 계정으로 다시 로그인합니다. 결재 상신 → 승인 → 회신처럼 역할이 바뀌는 흐름을 시나리오 하나로 검증할 때 씁니다.

📂 소스에서 만들기 (시나리오 초안을 한 번에)

편집 탭 메뉴 목록 의 📂 소스에서 만들기 → 프로젝트 소스 폴더를 지정하고 [분석 시작]. 서버가 안 떠 있어도 되고 로그인도 필요 없습니다 — 소스 파일만 읽어 접속 URL·로그인 설정·메뉴·금지 버튼·핵심 요소(expect) 후보를 만듭니다.

  • 메뉴는 메뉴 테이블 INSERT(MENU_NM+MENU_URL, 상위메뉴까지) → 화면 정의 XML → 메뉴 JSP → 컨트롤러(@GetMapping) 순으로 확신도가 높습니다. 각 줄에 출처와 근거(파일:줄)가 붙습니다.
  • 결과 위 📄 소스분석 보고서 에 메뉴별 근거와 뺀 것의 이유(POST 전용·API·모달·경로 변수·다운로드 등)가 전부 남습니다.
  • 저장·삭제 처리, 주석 처리된 옛 매핑, _backup 파일은 자동으로 뺍니다. 상세 진입과 조회 조건 값은 자동으로 넣지 않습니다(행 클릭이 데이터를 바꿀 수 있고, 날짜 형식을 모르기 때문) — 후보만 알려 줍니다.
  • 🖱 버튼 동작 검사도 만들기 를 켜면, 조회·검색·초기화처럼 데이터를 바꾸지 않는 버튼만 골라 actions 로 넣습니다 — 실행하면 그 버튼을 눌러 JS 에러·서버 오류·에러 알림·무반응(죽은 버튼) 까지 확인합니다. 저장·삭제·발송 버튼은 넣지 않고, 넣더라도 금지 버튼으로 차단됩니다.
  • 권한에 따라 달라지는 메뉴나 JS 로 그리는 메뉴는 소스에 없습니다 → 🔍 화면에서 메뉴 수집 으로 보완하세요.
  • 터미널: run.bat scan-source D:\source\myproject --out scenarios\프로젝트\초안.json

🔍 화면에서 메뉴 수집 (메뉴 목록 만들기)

편집 탭 메뉴 목록 의 🔍 화면에서 메뉴 수집 → 시작 화면과 깊이를 정하고 [수집 시작]. 로그인한 뒤 화면의 링크를 모아 메뉴 후보를 보여 줍니다.

  • <a href="#" onclick="goPage('/emp.do')"> 처럼 주소가 스크립트에 있는 메뉴, <a href="#none" menuurl="VOC1001" menupath="VOC 업무>전체 VOC"> 처럼 속성에 화면ID만 있는 메뉴(uxl/ub 등)도 찾아냅니다. 후자는 화면ID → URL 규칙(예: /screen/{}.ub)이 필요한데, 기존 메뉴가 있으면 자동으로 추론합니다.
  • 로그아웃·다운로드·엑셀·팝업·외부 링크, 금지 버튼 텍스트가 들어간 링크는 자동으로 뺍니다. 이미 목록에 있는 URL 은 "이미 있음" 으로 표시되고 체크가 꺼진 채로 나옵니다.
  • 메뉴 영역만 긁고 싶으면 링크 셀렉터에 #lnb a, .gnb a 처럼 지정하세요.
  • 초안입니다 — 목록 데이터 행(사람 이름 등)·팝업 전용 화면을 빼고, 이름을 대메뉴 > 소메뉴 로 다듬고, 필수 요소(expect)를 채운 뒤 저장하세요.

🖱 버튼 동작 검사 (actions)

화면이 뜨는지만 보지 말고 버튼을 눌러 동작까지 확인합니다. 버튼 하나가 결과표의 별도 행(↳ 메뉴 · 버튼)이 됩니다. 메뉴 JSON 에 "actions": [{ "name": "조회", "click": "#searchBtn", "expect": ["#list"] }] 처럼 넣습니다(편집 탭 JSON 직접 편집).

  • 따로 안 적어도 버튼 없음 · JS 에러 · 서버 5xx · 에러 알림 · 무반응(죽은 버튼) 을 잡습니다. expect·expectText·expectUrl·expectDialog 를 적으면 그것까지 확인합니다.
  • 금지 버튼(삭제·발송·저장…)은 누르지 않고 실패로 남깁니다. 데이터를 바꾸는 흐름은 ⏺ 녹화 → CRUD 로 만드세요.
  • 버튼을 누른 뒤에는 레이어를 닫고 원래 화면으로 되돌린 다음 다음 버튼을 누릅니다.
  • 소스가 있으면 📂 소스에서 만들기 의 🖱 옵션으로 안전한 버튼만 골라 자동 생성됩니다.

⏺ 녹화 (조작을 스텝으로)

편집 탭의 ⏺ 녹화로 흐름 만들기(CRUD) 또는 ⏺ 녹화로 클릭 진입 메뉴 추가(메뉴) → 시작 URL 을 넣고 시작하면 브라우저가 뜨고(로그인은 자동, 기록 안 함) 손으로 조작하는 대로 스텝이 쌓입니다.

  • 기록: 페이지 이동 · 클릭/더블클릭 · 입력(비밀번호칸은 {{password}}) · 선택 · 체크 · Enter/Esc · iframe 진입 · 새 창(팝업) · alert/confirm(자동 확인, expectDialog 로 기록)
  • 브라우저 상단 툴바: ☑ 요소 확인 → 다음에 클릭한 요소를 "보여야 함"으로 · 선택 텍스트 확인 → 드래그한 글자를 "있어야 함"으로 · 📸 캡처 · ■ 종료
  • 종료 후 스텝을 지우거나 JSON 을 손본 뒤 CRUD 흐름으로 추가 / 클릭 진입 메뉴로 추가. 저장 버튼 등 금지 버튼을 눌렀다면 ⚠ 표시 — 재생 시 차단되므로 allowForbidden 이 필요
  • 셀렉터는 id → name → title 등 속성 → 짧은 글자 → CSS 경로 순으로 고릅니다. 화면이 바뀌어 안 잡히면 JSON 에서 셀렉터만 고치면 됩니다
  • 터미널: run.bat record scenarios\프로젝트\x.json --url /emp/list.do --name "사원 등록" --append

셀렉터 찾기

브라우저에서 F12 → 요소 선택(Ctrl+Shift+C) → 입력란 클릭 → id 가 있으면 #id, 없으면 input[name=이름]. 로그인 버튼이 <div>/<img> 여도 그 요소의 id 로 지정.

    { "action": "expectText", "text": "TEST_자동" }
  ]}
]

증적 캡처: 실행 탭의 "증적 캡처"(모든 화면/실패만/안 찍음)가 전체 기본. 메뉴 행의 "증적" 열 또는 CRUD 흐름의 "screenshot": true|false 는 그 항목만 항상/절대 안 찍음으로 고정.
조회 조건: 편집 탭 "공통 입력값" 표(설명·필드·값)에 둔 값은 화면에 그 이름(name→id)의 입력란이 있을 때 채우고 "조회 버튼"을 눌러서 검사. 메뉴 행의 입력값 버튼 → 팝업에서 [화면에서 필드 가져오기]를 누르면 로그인 후 그 화면의 입력란(설명·종류·선택지)을 읽어와 값을 넣을 수 있음(공통값 덮어씀, 필드가 없으면 ❌). JSON: 최상위 "inputs": { "common": {...}, "labels": {...}, "search": "셀렉터" }, 메뉴 "inputs": {...}, "search": false|"셀렉터". 상세 진입 시 목록으로 돌아올 때도 재입력·재조회.
목록 → 상세: 메뉴 행의 "상세 진입 셀렉터"에 행/링크 셀렉터를 넣으면 목록 검사 후 위에서부터 "건수"만큼 클릭해 상세 화면을 ↳ 메뉴명 상세 #1 항목으로 따로 검사. JSON 으로는 "detail": { "selector": "tr.jqgrow", "rows": 2, "dblclick": true, "popup": true, "frame": "이름", "expect": ["#form"], "back": "goto|back|none" }. 목록이 비어 있으면 ⚠️ 로 기록.
액션: goto · click(selector|text, popup) · dblclick · fill · type · select · check · press(key) · frame(name|selector) · mainFrame · closePopup · wait(ms) · waitFor · waitForLoad · expectVisible · expectText · expectNotText · expectUrl(contains) · expectDialog · screenshot · eval · note
allowForbidden: 이 흐름에서만 금지 버튼(예: 저장)을 허용. 등록 데이터는 TEST_ 접두어 권장.

프로젝트 / 폴더 구조

scenarios/<프로젝트>/<폴더>/<시나리오>.json. 폴더 깊이는 자유(예: 우리은행VOC/권한/P01.json). 폴더의 ⋯ 메뉴로 하위 폴더 추가·이름 변경·삭제. 시나리오의 "저장 위치"를 바꿔 저장하면 이동. 터미널 일괄 실행: run.bat scenarios\우리은행VOC --mode menus --headless
